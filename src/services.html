Approach

How a project runs

I prefer small, reviewable increments over a long silent build. You should know what is being changed and why at each stage.

Scope the problem

Clarify the requirement, the current behaviour, and what "done" means. If the request hides a data or integration problem, that gets identified before implementation starts.

Build in increments

Implement the smallest working slice first, then extend it. Changes stay in Git with clear commits, and existing behaviour is checked before it is considered finished.

Hand over working software

Deploy what was built, document any configuration or environment requirements, and walk through the changes. You should be able to run and maintain the result.

Engagement terms: scope, deliverables, and timing are agreed in writing before work begins. I do not promise fixed delivery dates before understanding the codebase, and I do not take on work I cannot support with the technologies listed here.

Tell me what needs to work

A short description of the feature, bug, or integration is enough to start the conversation.
